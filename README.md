### Bagian 1: Rekayasa Perintah AI (*Prompt Engineering*)

Prompt Engineering merupakan seni dan teknik menyusun instruksi yang jelas, terkontekstualisasi, dan terarah agar model kecerdasan buatan (*Large Language Models*) menghasilkan keluaran yang akurat, relevan, serta minim halusinasi.

#### 1. Empat Komponen Kunci Perumusan Prompt (4-Pillar Prompt Framework)
Dalam menyusun perintah yang optimal kepada model kecerdasan buatan, terdapat 4 elemen mendasar yang wajib dipenuhi:
1. **Role (Peran):**  
   Menentukan persona atau identitas spesifik yang harus diadopsi oleh AI (misalnya: *Senior Software Architect*, *Dosen Pembimbing Jaringan*, atau *Technical Writer*).
2. **Task (Tugas Utama):**  
   Pernyataan tindakan eksplisit mengenai hasil kerja yang diminta (misalnya: *Buatkan struktur database*, *Analisis kompleksitas kode*, atau *Rangkum artikel berikut*).
3. **Context (Konteks & Batasan):**  
   Latar belakang situasi, data relevan, asumsi teknis, dan target pengguna yang menjadi acuan proses penalaran model.
4. **Format (Bentuk Luaran):**  
   Instruksi spesifik mengenai format penyajian hasil akhir (misalnya: *Tabel Markdown*, *Kode JSON valid*, *Poin-poin bernomor*, atau *Dokumen teknis formal*).

#### 2. Fungsi dan Manfaat Penerapan Prompt Terstruktur
- **Meningkatkan Performa Model AI:** Memandu model memprioritaskan bobot informasi yang esensial sehingga jawaban lebih presisi.
- **Mengurangi Bias dan Menghindari Respons Ofensif:** Menjaga luaran AI agar tetap berada dalam koridor etis, objektif, dan netral.
- **Meningkatkan Kontrol dan Prediktabilitas:** Memastikan model merespons sesuai batasan dan kriteria format tanpa penyimpangan interpretasi.
- **Memberikan Pengalaman Pengguna (*User Experience*) yang Lebih Baik:** Menghemat iterasi perbaikan karena jawaban yang didapat langsung siap digunakan.

### Bagian 2: Version Control System (VCS), Git, dan GitHub

Pengelolaan berkas proyek perangkat lunak modern menuntut adanya sistem pencatatan riwayat perubahan yang transparan dan aman.

#### 1. Definisi dan Filosofi Git
- **Git** adalah sistem pengontrol versi terdistribusi (*Distributed Version Control System* / DVCS) yang dirancang untuk melacak setiap perubahan pada berkas kode dari waktu ke waktu.
- Git mencatat informasi **siapa** (*author*), **kapan** (*timestamp*), dan **apa saja** (*diff / change log*) baris yang dimodifikasi, ditambah, maupun dihapus.
- Sistem Git diciptakan oleh **Linus Torvalds** pada tahun 2005 dalam rangka memfasilitasi pengembangan kernel Linux secara kolaboratif lintas dunia.
- **Perbedaan Git dan GitHub:**
  - **Git:** Alat atau *software* berbasis *command-line* yang berjalan secara lokal di komputer pengembang untuk mencatat riwayat perubahan berkas.
  - **GitHub:** Layanan komputasi awan (*cloud platform*) untuk meng-hosting repository Git, memfasilitasi kolaborasi daring, manajemen proyek, *issue tracking*, dan *pull request*.

#### 2. Tiga Wilayah Kerja Git (3 Working Areas in Git)
Arsitektur internal Git membagi berkas ke dalam tiga lapisan area kerja:

```
 +--------------------+       git add       +--------------------+      git commit      +--------------------+
 |                    |  ---------------->  |                    |  ----------------->  |                    |
 |  Working Directory |                     |    Staging Area    |                      |   Git Repository   |
 |   (Untracked/Mod)  |  <----------------  |      (Index)       |                      |   (.git directory) │
 +--------------------+      git restore    +--------------------+                      +--------------------+
                                                                                                   │
                                                                   git push                        │
                                                                 ──────────────────────────────────┘
                                                                 ▼
                                                    +-------------------------+
                                                    |  Remote Server (GitHub) │
                                                    +-------------------------+
```

1. **Working Directory (Direktori Kerja):**  
   Folder kerja aktif di komputer tempat berkas dibuat, diedit, atau dihapus secara langsung.
2. **Staging Area / Index (Area Persiapan):**  
   Lapisan perantara tempat berkas yang telah dipilih dikelompokkan dan disiapkan sebelum dibekukan ke dalam sebuah *commit*.
3. **Git Directory / Repository (`.git`):**  
   Penyimpanan basis data permanen tempat seluruh metadata dan *snapshot commit* tersimpan secara utuh dan aman.

#### 3. Ringkasan Perintah Dasar Git (*Git Cheat Sheet*)

| Perintah | Fungsi Utama |
| :--- | :--- |
| `git init` | Menginisialisasi repositori Git baru di dalam direktori kerja lokal. |
| `git clone <url>` | Mengunduh salinan repository yang berada di remote server ke komputer lokal. |
| `git status` | Memeriksa status berkas pada *Working Directory* dan *Staging Area*. |
| `git add <file>` / `git add .` | Menambahkan berkas ke dalam *Staging Area* untuk disiapkan pada *commit* berikutnya. |
| `git commit -m "pesan"` | Menyimpan snapshot perubahan dari *Staging Area* ke repository lokal disertai pesan deskriptif. |
| `git branch -M main` | Mengganti nama cabang (*branch*) utama menjadi `main`. |
| `git remote add origin <url>` | Menghubungkan repositori lokal dengan repositori remote di GitHub. |
| `git push -u origin main` | Mengunggah riwayat commit dari repositori lokal ke server remote GitHub. |
| `git pull origin main` | Mengambil dan menggabungkan perubahan terbaru dari remote GitHub ke repositori lokal. |

## 💡 Poin-Poin Penting dan Pengetahuan Baru (Key Learnings)

1. **Pentingnya Riwayat Perubahan Terstruktur:**  
   Menyadari bahwa mengandalkan salinan berkas manual seperti `tugas_final_rev2.zip` rawan redundansi dan kehilangan data. Git memberikan riwayat atomik (*atomic commits*) yang aman dan dapat dilacak kapan pun dibutuhkan.
2. **Format README.md sebagai Wajah Proyek:**  
   Berkas `README.md` bukan sekadar pelengkap, melainkan dokumentasi primer (*single source of truth*) yang menentukan keterbacaan, profesionalitas, dan kemudahan evaluasi suatu proyek perangkat lunak.
3. **Mindset Kolaboratif dalam Ekosistem TIK:**  
   GitHub membuka peluang kolaborasi terbuka melalui repositori berstatus *Public*, memungkinkan mahasiswa berbagi wawasan, menerima masukan teknis (*code review*), dan membangun portofolio digital sejak tingkat pertama.
4. **Kombinasi AI dan Version Control:**  
   Kecerdasan buatan dapat dimanfaatkan secara bertanggung jawab untuk membantu proses konseptualisasi kode dan dokumentasi, dengan tetap menerapkan kontrol validasi kritis sebelum dilakukan *commit* dan *push*.
